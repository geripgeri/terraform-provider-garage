# AGENTS.md

Compact guidance for work in this fork. Read before changing code or cutting a release.

## Why this fork exists

- Fork of `schwitzd/terraform-provider-garage`; upstream is unresponsive. Work here targets the Garage v2 admin API (current branch upgrades to the v2.5 spec) and aims to publish under `geripgeri` on the Terraform and OpenTofu registries.
- Identity is normalized to `geripgeri/terraform-provider-garage` in go.mod, Makefile `NAMESPACE`, `package.json`, and CHANGELOG links. The registry source address comes from the GitHub owner/repo (`geripgeri/garage`), not the Go module path.
- go.mod requires Go 1.24.5. The root `Dockerfile` is dev-tooling only and pins `golang:1.18` — too old to build this module.

## Commands (Makefile is the source of truth)

- `make test` — isolated `GOCACHE`, `-count=1 -race -covermode=atomic -parallel=4 -timeout=5m`, writes `coverage.out`. Focus one test with `make test TESTARGS='-run TestDetectGarageVersionV2Success' TEST=./garage`.
- `make testacc` — sets `TF_ACC=1` with a 120m timeout, but there are currently no `resource.Test` acceptance tests; all tests are `httptest`-based. Do not assume live-Garage coverage.
- `make docs` — calls hardcoded `~/go/bin/tfplugindocs` (install via `go install github.com/hashicorp/terraform-plugin-docs/cmd/tfplugindocs@latest`). Edit `templates/index.md.tmpl` and `examples/`; never hand-edit `docs/` — files carry `<!-- schema generated by tfplugindocs -->`.
- `make build` / `make local-install` derive VERSION via `git describe --tags --abbrev=0`; pass `VERSION=x.y.z` explicitly when tags are absent. `local-install` targets `~/.terraform.d/plugins/registry.terraform.io/geripgeri/garage/...`.
- Local Garage: `cd docker && sh setup.sh` (uses `docker-compose` v1, `network_mode: host`). Admin API on `:3903` with hardcoded token in `docker/garage.toml`; image is `dxflrs/amd64_garage:v2.5.0`.

## Architecture and API quirks

- Entrypoint: `main.go` → `garage.Provider()`; 4 resources (bucket, bucket_alias, bucket_key, key), no data sources. `pluginServe` is a package var swapped out in `main_test.go` — keep it injectable.
- Configure-time version check: `providerConfigure` probes `/v2/GetClusterStatus` via raw HTTP with lenient JSON decode (additive response fields are intentionally ignored), falls back to `/v1/status` only on 404/unknown-endpoint — never on 401/403 — and enforces Garage >= 2.0.0. Preserve this behavior when bumping the admin API.
- Garage SDK is a non-GitHub Go module, `git.deuxfleurs.fr/garage-sdk/garage-admin-sdk-golang`, pinned by pseudo-version in go.mod; `go mod download` needs access to that host.

## Release flow (why a dispatched run can produce no package)

- `.github/workflows/release.yml` is `workflow_dispatch` only and now fails fast with a clear error unless dispatched on `main`. Stage 1: semantic-release (`.releaserc`, `branches: ["main"]`) updates CHANGELOG.md/version, commits/tags and creates the GitHub release. Stage 2: GoReleaser builds signed artifacts, gated on `steps.release.outputs.new_release_published == 'true'`.
- Only `feat`/`fix`/`perf`/`BREAKING CHANGE` commits since the last tag trigger a release; `chore:`-only commits do not. This checkout has no git tags — verify the fork actually has the upstream `v*` tags (`git ls-remote --tags origin`), since semantic-release needs a last-release baseline.
- Two regressions from `a838afb` are fixed here: the "Re-checkout after semantic-release" step (added in `7a66a0a`, needed because GoReleaser's `before` hook runs `go mod tidy` on a clean tree) and the `@semantic-release/changelog` plugin config. Don't drop either again; the workflow declares `permissions: contents: write` for release creation.
- Secrets: `GPG_PRIVATE_KEY`, `PASSPHRASE`, `GITHUB_TOKEN`. GoReleaser signs the checksum file with `--local-user $GPG_FINGERPRINT` from the import step; upload the matching public key to both registry accounts.
- `.goreleaser.yml` emits registry-compatible assets: `<project>_<version>_<os>_<arch>.zip`, `<project>_<version>_SHA256SUMS` + `.sig`, and `<project>_<version>_manifest.json`. The manifest must say protocol `5.0`: SDKv2's `plugin.Serve` uses `tf5server`, so a `6.0` manifest makes registry installs fail handshake.
